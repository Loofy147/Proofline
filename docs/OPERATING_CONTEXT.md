# Operating Context

Proofline is a local-first MVP intended to support one repeatable paid verification outcome before broad platform investment.

## Inside the repository

Issues → acceptance criteria → focused implementation → CI and independent checks → review → release checklist → observation of failures and customer outcomes.

## Outside the repository

Independent criticism, primary-source checks, separate calculations, usability assessment, customer interviews, and pilot review. Material findings return as issues, decision records, tests, or roadmap changes.

## Current capabilities and limits

- Browser app and Python standard-library CSV checker.
- GitHub Actions CI.
- Human review and independent verification where needed.
- No backend, customer-upload server, account system, model-to-model orchestration, payment processing, external connectors, or scheduled execution.

Before changes, read the project context and architecture docs. At handoff, report files changed, checks actually run, results, and gaps. Never trust a model summary over source code or current CI evidence.
